# A3.4.1 / J01 — Android App Check (Debug + Play Integrity)

This document describes **how** Android selects App Check providers.
It intentionally contains **no token values**.

## Canonical environment pairs (fail closed otherwise)

| Environment | Firebase project | App Check |
|-------------|------------------|-----------|
| `development` | `nearsy-dev` | Debug |
| `production` | `nearsy-pj` | Play Integrity |

Mismatched pairs (e.g. development + nearsy-pj) **reject** initialization.
Production **never** uses Debug and **never** embeds a debug token.

## Development (nearsy-dev)

### When Debug is needed

Callable Functions (LinkedIn A3, and later OTP / Affiliations / Visibility)
use `enforceAppCheck: true`. Emulators / local debug builds must use the App
Check **Debug** provider and a token registered in the Firebase Console for
`nearsy-dev` only.

### Preconditions

- Build profile: EAS `development-nearsy-dev` **or** local run with
  `NEARSY_FIREBASE_ENV=development` (selects `google-services.nearsy-dev.json`).
- Expo extras must include `nearsyFirebaseProjectId: 'nearsy-dev'`.
- App Check bootstrap selected **Debug** (development env + development
  client / `__DEV__`).
- Never register a Production token into `nearsy-dev`, and never reuse a
  `nearsy-dev` token on Production.

### Owner steps (private)

1. Install a Development client build that targets **nearsy-dev**.
2. Launch the app once so App Check Debug initializes.
3. Read the debug token from **logcat** / Android Studio Logcat (React Native
   Firebase / Firebase App Check debug provider output). Do not paste it into
   chat, git, `.env`, screenshots in the repo, or tickets.
4. In Firebase Console → **nearsy-dev** → App Check → Manage debug tokens →
   register the token for the Android app `com.nearsy.app`.
5. Relaunch and confirm callables no longer fail with App Check
   `UNAUTHENTICATED` / `app=MISSING`.

## Production (nearsy-pj) — Play Integrity

### Code behavior (J01)

- EAS `production` / `preview` set `NEARSY_FIREBASE_ENV=production`.
- Bootstrap configures RNFB Android provider `playIntegrity`.
- Debug provider / debug tokens are forbidden.

### External configuration still required (not done in-repo)

1. **Firebase Console (nearsy-pj)** → App Check → register Android app
   `com.nearsy.app` with **Play Integrity** provider; enforce on callables
   as already configured by backend.
2. **Google Play Console** → app signing / Play Integrity API linkage for
   the package (required for Integrity tokens on release builds).
3. **Physical / EAS production-like build** on a device or internal track to
   confirm tokens are accepted by backend callables.

## Agent rules

- Agents must **not** read, print, store, or register debug tokens.
- Agents must **not** disable `enforceAppCheck` on the backend.
- Agents must **not** commit tokens or put them in documentation.
- Agents must **not** skip App Check for production builds.

## Callable token foundation

After `ensureAppCheckInitialized` reaches `ready`, React Native Firebase
attaches App Check tokens to `httpsCallable` automatically. Modules may also
call `ensureAppCheckTokenFoundation()` to assert readiness before later
Journeys (OTP, Affiliations, Visibility).

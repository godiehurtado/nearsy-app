# A3.4.1 — App Check Debug token (owner procedure)

This document describes **how** to obtain and register an App Check **debug**
token for Android Development against **`nearsy-dev`**. It intentionally
contains **no token values**.

## When this is needed

Callable Functions `linkedinAuthStart` / `linkedinAuthExchange` use
`enforceAppCheck: true`. Emulators / local debug builds must use the App Check
**Debug** provider and a token registered in the Firebase Console for
`nearsy-dev` only.

## Preconditions

- Build profile: EAS `development-nearsy-dev` **or** local run with
  `NEARSY_FIREBASE_ENV=development` (selects `google-services.nearsy-dev.json`).
- App Check bootstrap selected **Debug** (Development Firebase env + development
  client / `__DEV__`).
- Never register a Production token into `nearsy-dev`, and never reuse a
  `nearsy-dev` token on Production.

## Owner steps (private)

1. Install a Development client build that targets **nearsy-dev**.
2. Launch the app once so App Check Debug initializes.
3. Read the debug token from **logcat** / Android Studio Logcat (React Native
   Firebase / Firebase App Check debug provider output). Do not paste it into
   chat, git, `.env`, screenshots in the repo, or tickets.
4. In Firebase Console → **nearsy-dev** → App Check → Manage debug tokens →
   register the token for the Android app `com.nearsy.app`.
5. Relaunch the app and confirm callables no longer fail with App Check
   `UNAUTHENTICATED` / `app=MISSING` (after LinkedIn client callables exist).

## Agent rules

- Agents must **not** read, print, store, or register debug tokens.
- Agents must **not** disable `enforceAppCheck` on the backend.
- Agents must **not** commit tokens or put them in documentation.

## Out of scope for A3.4.1

Play Integrity (Release), iOS DeviceCheck/App Attest, and Production App Check
enforcement are deferred.
